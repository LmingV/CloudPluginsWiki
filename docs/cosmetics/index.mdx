## 为什么选择云时装

市面上很多时装方案只做到「把模型放到玩家身上」，但真正上线后才会遇到：转身时翅膀慢半拍、传送后模型卡在原地、主城人一多客户端直接掉帧。
**云时装从第一版起就围绕「跟得紧、不卡住、扛得住人多」反复打磨**，这些问题在插件里都有对应的机制，而不是交给服主自己想办法。

## 功能一览

| 模块 | 能做什么 |
| --- | --- |
| 渲染模式 | `meg` 骨骼动画模型、`display` 浮空物品、`equipment` 原版装备外观、`body` 贴身展示 |
| 跟随与转向 | 逐 tick 同步、三种转向模式、朝向相关偏移、BODY 四种锚点 |
| 动画 | 按待机、行走、潜行、飞行、游泳自动切换动画 |
| 收藏与解锁 | 时装卡右键永久解锁，已拥有不重复消耗；管理员可直接给予或收回 |
| 商城 | 接入 Vault 经济，购买失败自动退款，并发购买保护 |
| 属性 BUFF | 拥有即生效、多件叠加（MythicLib），不必强制穿戴 |
| 不死图腾 | 穿戴指定时装时触发原版图腾保命，可设冷却与恢复血量 |
| 物品来源 | 原版 CustomModelData / item-model、ItemsAdder、CraftEngine |
| 菜单 | 分类页、衣橱、商城全部可自定义，自动分页，防止拿取物品 |
| 图腾提示 | 冷却倒计时可选 BOSS 血条 / 快捷栏文字，或用 PlaceholderAPI 变量自行显示 |
| NPC 展示 | 一条指令在当前位置生成穿着时装的 Citizens NPC |
| 可见性 | 玩家可隐藏自己的时装，或隐藏其他玩家的时装 |
| 数据 | SQLite 单服、MySQL / MariaDB 跨分流共享 |
| 权限 | 细分到每条管理指令的权限组，兼容旧版权限 |
